# Observability for LLM Inference on Kubernetes

**Event:** KubeCon + CloudNativeCon North America 2026 · Track not yet assigned  
**Speakers:** Oscar Castillo (Genius Sports), Jeffry Hernández (Wizeline)  
**Video:** [YouTube](https://www.youtube.com/watch?v=4T2887KV_WM) (24:35)  
**Slides:** [Find slides on Sched](https://kccncna2026.sched.com/search?q=Observability+for+LLM+Inference+on+Kubernetes)  
**Tags:** `ai-inference`, `observability`, `opentelemetry`, `gpu-metrics`

> With frontier APIs you only see the client side, but self-hosting on Kubernetes lets you observe every layer from the GPU up to the user response. The speakers instrument an OCR app on KServe, vLLM and llm-d with OpenTelemetry and correlate metrics, traces and logs in Grafana to find wasted tokens and misleading GPU utilization.

## Key points

- Inference has a prefill stage and an iterative decode stage, which give the two core metrics: time to first token and time per output token. [1:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=60s)
- With frontier model APIs you can instrument your app with OpenTelemetry GenAI traces, but not model internals, GPU use or KV cache, and provider features change over time. [3:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=180s)
- Provider-reported TTFT differed from client-measured TTFT because of network hops and client processing. [5:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=300s)
- With a local model capped at four parallel requests, extra requests show up as deferred, which is what a slow chat response feels like. [7:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=420s)
- Demo app: passport OCR using an open-weights Qwen 9B vision model on one Kubernetes GPU node with KServe and vLLM, llm-d routing and Envoy Gateway in front. [10:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=600s)
- Signals span five layers: application, routing (scheduler latency), inference server (TTFT, KV cache), hardware (GPU) and Kubernetes (vLLM startup, scheduling, unhealthy events). [11:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=660s)
- DCGM dashboards show a GPU at 100% utilization while KV cache was only 20% busy, so GPU utilization alone misleads. [14:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=840s)
- OpenTelemetry traces cover model loading in vLLM and full request paths, including a failed span whose cause was an empty model response. [16:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=960s)
- The OpenTelemetry Collector sends signals to Prometheus, Tempo and Loki; correlation uses exemplars, trace ID queries, span metrics and the GenAI semantic conventions. [19:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=1140s)
- Findings: thinking mode wasted tokens for the vision model without improving answers, and batching many requests at once saved cost and energy. [21:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=1260s)

## Numbers stated

- OpenAI test script: 5 requests, about 100 tokens per second throughput. [4:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=240s)
- Provider dashboard showed 600 ms TTFT while the client measured about 1.5 seconds. [5:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=300s)
- Local model configured for 4 parallel requests; GPU utilization near 90% under load. [8:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=480s)
- GPU at 100% utilization with KV cache only 20% busy. [14:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=840s)
- Compared 1 request versus 24 requests at once for cost and energy. [21:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=1260s)

## Open gaps

- Hosted frontier APIs hide model internals, GPU and KV cache behavior from users. [3:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=180s)
- On neo-cloud GPUs you do not own the hardware, so power and energy data is not accurate. [14:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=840s)
- The OpenTelemetry GenAI semantic conventions are still in development. [19:00](https://www.youtube.com/watch?v=4T2887KV_WM&t=1140s)
